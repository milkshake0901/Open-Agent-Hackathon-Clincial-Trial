# Public HTTP API (consumed by the Next.js frontend)

Base: `http://localhost:8000/api`. JSON unless noted. Wire schemas live in `app/api/schemas.py` and are built from domain types; the frontend generates TS types from `/openapi.json`. Long work returns `202` with a `run_id`; the UI follows the run.

| Method | Path | Request | Response | Facade call |
|---|---|---|---|---|
| POST | `/patients` | `{label}` | `201 {patient_id}` | insert |
| POST | `/patients/{pid}/documents` | multipart `file` (one PDF per request; several at once are several requests) | `202 {document_hash, run_id, deduplicated: bool}`; the PDF is read page by page with Nemotron Parse, de-identified as one Document, and stored as pages and Regions with boxes; a re-upload of the same bytes is not read again and answers with the earlier run unless it was rejected; `422` unreadable (empty, not a PDF, or the parse found no readable text: nothing but page headers and footers), `413` over 20 MB | `record.register_document` then bg `record.ingest` → `matching.rescan` on Committed (same run_id) |
| GET | `/questionnaire/definition` | | `{version, sections: [{id, title, questions: [{id, number, label, label_other, kind, options, required, help}]}]}` | `record.questionnaire_definition` |
| POST | `/patients/{pid}/questionnaire` | `{definition_version, respondent: patient\|other, answers: {question_id: value}}` | `202 {document_hash, run_id, deduplicated, return_token?}`, always, whatever the run's outcome; follow `GET /runs/{run_id}` for it (`committed` with `profile_version_id`, `awaiting_patient` or `rejected` with `reason`). Answers identical to the latest accepted submission answer with its run (`deduplicated`). `422` an answer that does not fit its question or an out-of-date definition, `404` unknown patient | `record.register_questionnaire` then bg `record.ingest` → `matching.rescan` on Committed (same run_id), exactly like an added Document |
| GET | `/patients/{pid}/questionnaire` | | `{definition_version, document_hash, respondent, answers}` (latest accepted submission, to prefill an edit; never the postcode or contact); `404` before the first | `record.latest_answers` |
| PUT | `/patients/{pid}/search-preferences` | `{postcode?, max_travel_km?: 10\|25\|50\|100\|anywhere, contact?}` (as the questionnaire takes them; a field left out or blank keeps its stored value) | `200 {postcode_set, location_known, max_travel_km, contact_set}`; the postcode and contact are never sent back. Not a Fact: no new Profile version. `422` a value that does not fit its question, `404` unknown patient | `record.set_search_preferences` |
| GET | `/documents/{hash}/regions` | | `{document_hash, filename, page_count, regions: [{span_id, page, ordinal, kind, text, x0, y0, x1, y1}], document_date, date_order}`: the de-identified Regions read from a stored Document, in reading order; boxes are fractions of the page image, origin top left. `document_date` (ISO date or null) is the Document date read from its first page; `date_order` is `day_first`, `month_first` or null (no date settles it, so its ambiguous dates are flagged). `404` unknown Document | `record.document_regions` |
| GET | `/documents/{hash}/pages/{n}/image` | | `image/png`: the stored PDF page rendered as it was parsed, so a Region's box (fractions of this image, origin top left) lines up with its words. `404` unknown Document or page | `record.page_png` |
| GET | `/patients/{pid}/documents` | | `[{hash, filename, page_count, uploaded_at, version_number?}]` | `record.*` |
| GET | `/patients/{pid}/documents/{hash}/pages/{n}` | | `{number, text, tables}` (de-identified) | citation viewer |
| GET | `/patients/{pid}/versions` | | `[{id, number, document_hash, fact_count, created_at}]` | `record.versions` |
| GET | `/patients/{pid}/versions/{vid}` | | `{id, number, facts: [{id, resource, subject, value, unit, observed_on, flags, flagged, citation:{document_hash,page,quote,span_id}}], current: {subject: fact_id}}`. `flags` says how `observed_on` was settled: `ambiguous_date`, `estimated_date` (a relative date counted back from the Document date), `document_date` (none of its own); `flagged` is true for an ambiguous date or an estimate | `record.profile_version` |
| GET | `/patients/{pid}/versions/{vid}/diff?from={vid0}` | | `{facts_added: [...], subjects_changed: [{subject, before?, after}], verdicts_changed: [VerdictChange]}` | `record.diff` + `matching.change_between` per trial |
| GET | `/runs/{run_id}` | | `{run_id, kind, head, state: IngestRunState \| null, events: [{seq, at, kind, actor, causation_id, payload}]}`; an ingest's `state.phase` is `started\|drafting\|awaiting_patient\|awaiting_review\|committed\|rejected`, with `version_number` and `reason` | `trace.read` + `reduce_ingest` |
| GET | `/runs/{run_id}/events?since={seq}` | | `{head, events: [{seq, at, kind, actor, summary, payload}]}` (poll every ~1 s; SSE optional) | `runs.read(since_seq)` |
| GET | `/runs/{run_id}/conflicts` | | `{run_id, conflicts: [{id, message, draft, accepted}]}`; each side `{document_hash, filename, page, page_text, quote, value, unit, observed_on, label}`; empty once the run moved on | `record.conflicts` |
| POST | `/runs/{run_id}/confirm` | `{resolutions: [{conflict_id, choice: keep_accepted\|accept_draft\|discard_both}]}` | `202 {run_id, outcome: committed\|awaiting_patient\|awaiting_review\|rejected, document_hash?, profile_version_id?, version_number?, reason?, rescan?: {judged, failed}}`; Re-scan runs inline on committed; a letter's run goes on to `awaiting_review`; `422` unknown Conflict | `record.confirm` |
| GET | `/runs/{run_id}/review` | | Letter review of a run in `awaiting_review`: `{run_id, document_hash, filename, page_count, document_date, document_date_corrected, date_order, facts: [{index, resource, subject, value, unit, observed_on, page, quote, region: {span_id, kind, text, x0, y0, x1, y1} \| null, flags, flagged, decision: keep\|drop\|null, correction}]}`, flagged Facts first; boxes are drawn on `/documents/{hash}/pages/{page}/image`. `404` unknown run, `409` not awaiting review | `record.letter_review` |
| POST | `/runs/{run_id}/review/facts/{index}` | `{decision: keep\|drop, correction?}` | the review as above. `keep` is "Looks right" (committed checked), `drop` "Not right" (never committed); `correction` (drop only, ≤500 chars) is what it should be. `422` no such Fact or a correction on keep, `409` not awaiting review | `record.answer_review` |
| PUT | `/runs/{run_id}/review/document-date` | `{document_date}` | the review as above, with the Facts the Document date dated (no date of their own, or "4 months ago") re-dated by the correction. `422` a date after today | `record.correct_document_date` |
| POST | `/runs/{run_id}/review/commit` | | `202 {run_id, outcome: committed, profile_version_id, version_number, correction_run_id?}`: kept Facts checked, unanswered ones not checked, dropped ones never. The corrections are added to the questionnaire answer Q16 (`letter_corrections`, review only) and ingested in the background under `correction_run_id`; the Re-scan follows the last commit. `409` not awaiting review (a review commits once) | `record.commit_review` then bg `record.ingest` / `matching.rescan` |
| POST | `/runs/{run_id}/review/use-all-as-read` | | as `commit`, with every drafted Fact committed as read, none checked, no corrections | `record.commit_review(use_all_as_read=True)` |
| GET | `/trials` | | `[{nct_id, title, status, criterion_count, eligibility_hash, fetched_at, source}]` | `trials.active_trials` |
| GET | `/trials/{nct}` | | `{nct_id, title, status, page_url, sponsor, responsible_party: Contact \| null, central_contacts: [Contact], overall_officials: [Contact], sites: [{facility, city, status, contacts: [Contact]}], outcomes: {primary, secondary, other: [{measure, description, time_frame}], has_results, results: [{type, title, description, time_frame, unit, param_type, values: [{group, value, spread, lower, upper, label}]}], publications: [{pmid, type, citation, url}]}}`, Australian sites only; `Contact` is `{name, role, email, phone, affiliation, title}` with `""` for fields the registry omits (likewise Outcome fields; a publication's `url` is its PubMed page, `""` without a PMID). Unknown NCT → `404` | `trials.trial` + `trials.contacts` + `trials.sites` + `trials.outcomes` |
| GET | `/trials/{nct}/outcomes/summary` | | `{nct_id, summary}`: a plain-language summary of the Trial's Outcomes (#26), written by one fast-lane model call on the first ask (never at ingest) and reused while the Outcomes are unchanged. `404` unknown Trial, `503` model unavailable (nothing is cached, so a retry asks again) | `trials.outcome_summary` |
| GET | `/patients/{pid}/closed-trials` | | `{condition_term, trials: [{nct_id, title, status, conditions, closed_on, url}]}`: Closed trials (ADR 0004) listing one of the patient's Condition term labels (ADR 0005; `condition_term` is the ticked labels), newest first by `closed_on` (primary completion, else completion, else last update). No Verdict: never judged. Empty with `condition_term: null` until a Diagnosis check has ticked labels | `record.diagnosis_step` + `trials.closed_trials_with_labels` |
| GET | `/patients/{pid}/versions/{vid}/trials/{nct}/enquiry` | | `{nct_id, details: [{id, label, text, included: true}]}`: the de-identified clinical details an Enquiry may include, all ticked, shown to the Respondent before anything is drafted. No model call. `404` unknown Trial | `enquiry.details` |
| POST | `/patients/{pid}/versions/{vid}/trials/{nct}/enquiry` | `{include: [detail id]}` (required: the details the Respondent confirmed; `[]` for none) | `{nct_id, template: open \| closed, subject, body, recipient: {name, email, kind: site \| central \| responsible_party \| official, facility} \| null, sponsor, details: [{id, label, text, included}]}`. An email body for the Respondent to edit, copy and send themselves: an Open trial's (`template: open`) asks about taking part, citing its Verdict and asking about its unknown Criteria when it has one at this version (none yet: no Verdict is mentioned); a Closed trial's (`template: closed`, also for a Trial that closed after it was judged) asks about its Outcomes or a follow-on study. Recipient, Open trial: nearest Australian site contact with an email, else central contact; Closed trial: the responsible party where the Trial lists them with an email, else an overall official with one; `null` when the Trial lists no email, and the greeting then names the sponsor's trial team. Name and contact are placeholders; details not in `include` never reach the model. Nothing is stored or sent. `404` unknown Trial, `422` no `include`, `503` model unavailable | `enquiry.draft` |
| POST | `/patients/{pid}/trials/{nct}/ask` | `{question}` (≤ 500 characters) | `{nct_id, title, question, standing: eligible \| possible \| excluded \| needs_information, answer, to_gather: [line], via: zetaris \| postgres, citations: [GroundedCitation], misses: [{criterion_id, clause, why, citation: GroundedCitation}]}`, `GroundedCitation` = `{span_id, document_hash, filename, page, quote, x0, y0, x1, y1}`. A free-form question of one Trial from its Verdict on the Trials page, for any condition: one deep-lane call sees the question, the Trial's Criteria and the patient's Regions of the kinds Intake reads (Text, Title, Section-header, List-item, Table, Caption), read through the agent reader. Code keeps only cited ids that are the patient's Regions (the quote is the stored Region text), and a miss only when its clause is verbatim from a stored exclusion; a firm eligible or excluded answer with no citation becomes `needs_information`. Not saved; changes no Verdict. `404` unknown patient or Trial, or no Document read into Regions; `422` empty or too long; `503` model unavailable | `matching.ask_trial` |
| POST | `/patients/{pid}/versions/{vid}/rescan` | | `202 {run_id}` (manual; idempotent — a no-op rescan finishes immediately with `rescan.planned` showing all skipped). With no Condition term it judges nothing and calls no model (ADR 0005): `rescan.planned` lists nothing to judge and nothing skipped, and the log file gets `matching.rescan.no_condition_term` | `matching.rescan` |
| GET | `/patients/{pid}/versions/{vid}/verdicts` | | `{profile_version_id, condition_term, diagnosis, verdicts: [Verdict]}`: only Trials listing one of the patient's Condition term labels (ADR 0005; `condition_term` is the ticked labels). `diagnosis` is the diagnosis step: `ticked` (labels ticked), `not_sure` (answered not sure: it waits on the GP) or `unfinished`. With no Condition term (`not_sure` or `unfinished`) `condition_term` is null and `verdicts` empty. Ranked by outcome (possible: fewest unknowns first), then nearest recruiting site; each Verdict also has `nearest_site: {name, status, km} \| null` (nearest recruiting site), `sites: [{name, status, km}]` (3 nearest open sites) and `further_away: bool` (no recruiting site within the travel limit; listed, never dropped). `km` is null when the distance is unknown. The postcode is never returned | `matching.verdicts_for_version` |
| GET | `/patients/{pid}/versions/{vid}/verdicts/{nct}` | | `{nct_id, outcome, eligibility_hash, stale: bool, attempts, unsupported_downgraded, run_id, results: [{criterion:{id,kind,text}, outcome, rationale, citation?: {fact_id, document_hash, filename, page, quote, question, label, region: {span_id, x0, y0, x1, y1} \| null, answer: {wording, text, quote_start, quote_end} \| null, checked: bool \| null}}], questions: [{criterion_id, subject, text}], respondent_questions: [{criterion_id, question_id, question, subject, text}]}`. A Citation's `region` is set for a Fact read from a letter: its Region (one of `/documents/{hash}/regions`) and box, to draw on `/documents/{hash}/pages/{page}/image`. Its `answer` is set for a Patient-reported Fact: the wording of question `question` as the Respondent saw it, the whole answer, and the quote's character offsets in it (`null` when not verbatim). `checked` is set for a letter Fact: whether the Respondent checked it in Letter review ("checked by you" / "not checked"); the list endpoint's Citations have the same shape. Each result also has `context_facts: [Citation]`: on an unknown result, the Context Facts it considered (only Facts of this Profile version), shaped like `citation`; `[]` otherwise | `matching.verdict` |
| GET | `/patients/{pid}/versions/{vid}/verdicts/{nct}/change?from={vid0}` | | `VerdictChange {outcome_from, outcome_to, criteria_changed: [{criterion_id, text, outcome_from, outcome_to, citation?}]}` | `matching.change_between` |
| GET | `/patients/{pid}/questions?version={vid}` | | `[{criterion_id, nct_id, subject, text, unblocks[]}]` deduped by subject; `criterion_id`/`nct_id` are `null` on the patient-level diagnosis question (subject `diagnosis`), listed first when the diagnosis needs the GP | `matching.questions_for_version` |
| GET | `/patients/{pid}/respondent-questions?version={vid}` | | `[{criterion_id, nct_id, question_id, question, subject, text, unblocks[]}]` deduped by questionnaire question; answer by resubmitting the questionnaire | `matching.respondent_questions_for_version` |
| GET | `/traces/{correlation_id}` | | causal tree of every event across an ingest and its Re-scan, with `llm_call` rows (requested vs answered model) | `trace.causal_tree` |
| GET | `/health` | | `{postgres, zetaris, nightshift: {ok, lanes: {fast, deep, judge}}, world_model}` | startup checks |
| GET | `/return/{token}` | | `{patient_id, profile_version_id?, version_number?}`; unknown token → bare `404`. The token comes once, as `return_token` on the first `POST /patients/{pid}/questionnaire` response | `record.patient_for_return_link` + `record.current_version` |
| POST | `/patients/{pid}/questionnaire/diagnosis-check` | | `201 {id, text, shortlist: [{label, open, closed}], ticked, status, needs_gp, message}` for the latest diagnosis answer (new words come with a `none_of_these` answer): up to 6 Condition labels stored Trials use (ADR 0005), best fit first, each with its Open and Closed trial counts; status `proposed`. An empty `shortlist` means no label fits: the Respondent can only re-word or answer not sure. Two fast-lane model calls that see only the diagnosis words and candidate labels. `404` no patient or no diagnosis answer, `503` model unavailable | `record.check_diagnosis` |
| POST | `/patients/{pid}/questionnaire/diagnosis-check/{id}` | one of `{answer: "ticked", labels}`, `{answer: "none_of_these", text}`, `{answer: "not_sure"}` | same shape. `ticked` with `labels` (one or more from the shortlist, matched ignoring case and spacing) settles the Condition term (`ticked` = the ticked labels) and re-scans the current version inline: `rescan: {judged, failed}`. `none_of_these` with `text` (the diagnosis in other words) starts and returns a new check for those words, `proposed`. `not_sure` → `needs_gp`. `404` not this patient's check, `409` already answered (before labels or new words are looked at), `422` an answer in another shape (unknown answer, no labels, no text), labels not in the shortlist or text with no words, `503` model unavailable (new words) | `record.answer_diagnosis_check` |

Errors: `404` unknown ids; `409` when `/confirm` is called on a run not in `awaiting_patient`, or a `/review` call on one not in `awaiting_review`; `422` validation; `503 {reason}` when Nightshift is unavailable (runs then end `run.rejected` / `rescan.finished` with `failed`).

Frontend pages → endpoints: Questionnaire (`questionnaire`, then `runs/{id}` until it ends), Upload+timeline (`documents`, `versions`, `runs/{id}/events`), Ranked trials (`verdicts`, `verdicts/{nct}`, `change`, then `closed-trials` in its own section), Trace page (`runs/{id}`), Doctor questions (`questions`), Respondent questions (`respondent-questions`), Conflict dialog (`runs/{id}/conflicts` + `confirm`), Letter review (`runs/{id}/review`, its answers, `commit` or `use-all-as-read`).
