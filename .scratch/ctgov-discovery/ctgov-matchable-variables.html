TrialMatch · ClinicalTrials.gov field discovery

What we can match a patient on

We checked every field in ClinicalTrials.gov API v2 against real recruiting Trials, to find which ones a patient's Facts could be checked against. We also mined each Trial's eligibility text to see what its Criteria ask about.

Key findings

  • Age, sex and site location are the only structured patient checks, and our Facts can't hold any of them. minimumAge is filled for 100 / 75 / 98% of studies, sex for 100%, and site geoPoint for at least 99%. Patients have no date of birth, sex or location.
  • Diagnosis is structured, but too coarse for oncology. Conditions are 100% filled and MeSH terms 96 / 93 / 82%. Histology, stage, line of therapy and relapse status exist only in free text.
  • Most Criteria are free text. In NSCLC Trials, prior treatment is mentioned by 97%, stage or extent by 98%, biomarkers by 90%, labs by 78%, performance status by 78% and CNS metastases by 76%.
  • About half of lab thresholds can be checked without a model. 35 / 49 / 51% of lab mentions carry a number and a unit. Many are "× ULN", which needs the lab's reference range, and the fact table has no column for it.
  • The API's distance filter isn't enough. filter.geo keeps a Trial if any site is within range, whatever that site's status. We need a per-site check.
  • The trial table throws away almost everything structured: age bounds, sex, phases, MeSH terms, interventions and sites.
  • Zetaris hasn't been tested yet. The probe SQL and its expected results are ready. The page it registers is 4.0 MB of JSON, so payload size is the first thing to check.

Gaps in our patient model

A Fact's resource can only be Condition, Observation, MedicationStatement or Procedure. Performance status, pregnancy status, biomarkers and weight all fit Observation. The variables below don't fit anywhere. De-identification removes date of birth and address, so age and location have to be stored as coarse values.

Paging, reasoned from the API

A REST table is one fixed URL, so it holds one page. The next page's token is only known after reading the response, so each page has to be fetched outside Zetaris first and registered as its own table, then joined with UNION ALL.

Sample A fits in one page. Sample B would need 7 tables at 100 per page, or one table of about 10 MB at 1,000 per page.

Expected outcome: Zetaris works for a single bounded page of up to 1,000 Trials. Anything larger uses the HTTP fallback in ctgov.py.

API caveats

Data

  • filter.geo matches on any site, whatever that site's status.
  • geoPoint is listed as a leaf in /studies/metadata, but study JSON returns a {lat, lon} struct.
  • Eligibility text is markdown with escapes (\<, \>, 1\.). Unescape it before parsing.
  • Text ages that differ from the structured minimum (B: 32 of 200, C: 9 of 186) are mostly conditional, for example "Karnofsky if ≥ 16 years". A few are genuinely stricter sub-cohort limits.
  • Splitting failed for 2 / 56 / 64 studies. Causes: only one heading (82), no headings (35), or headings written as bullets or numbers.

Endpoints

  • Every endpoint and parameter in the plan exists in the live OpenAPI spec.
  • /stats/field/sizes returns 404 for the whole request if any listed field isn't itself a list (e.g. InterventionName). Query one field at a time.
  • Results are unordered by default, so use sort for reproducible samples. countTotal only works on the first page. pageSize is capped at 1,000.
  • One page of 96 NSCLC Trials is 4.0 MB. The field list below cuts it by 37.5%. Site lists dominate the size.
  • 29 live calls, at least 1.3 s apart, no 429 responses.

Recommendations

Check deterministically

  • Age and sex gates
  • Distance to the nearest recruiting site
  • Performance status (scale and threshold, with the scale picked by age)
  • Labs with absolute units, and "× ULN" once Facts carry a reference range
  • Named biomarkers, when the Observation is coded
  • Named prior or current drugs, using other names and MeSH terms as synonyms
  • Body weight

Use the model, or ask the doctor

  • Model extracts, code checks: washout windows and lines of therapy, using date arithmetic on each Fact's observed-on date
  • Model: histology, stage and relapse wording; measurable disease; comorbidities; whether CNS metastases are active or stable
  • Always a Doctor question: investigator judgement, life expectancy, and pregnancy or contraception at screening
